Week 1 — Day 1 · GitHub & VS Code

On the first day of my internship at Tinkerers' Lab, I was introduced to two foundational tools that every developer uses: GitHub for version control and VS Code as a code editor. I set up my development environment from scratch — installed VS Code, configured my GitHub account, created my first repository, and successfully pushed it to GitHub directly from the terminal inside VS Code. It was a hands-on start that immediately made things feel real.

What is GitHub?

GitHub is a web-based platform for version control and collaborative software development, built on top of Git. Think of it like Google Drive for developers — a place to store your code online, track every change you make, and collaborate with others without overwriting each other's work. Every project lives in a repository, and every change is recorded as a commit — giving you a complete history of what was built, when, and why.

For internship and portfolio purposes, GitHub also serves as a public showcase of your work — recruiters and mentors can see exactly what you have built.

To get started, navigate to your GitHub profile and click the "New" button to create a repository. Give it a meaningful name and a short description of what it contains. A good repository name is lowercase, uses hyphens instead of spaces, and clearly reflects the project — for example, arduino-radar-system or internship-portfolio.

Always enable the "Initialize this repository with a README" option before creating the repo. This creates an initial file in the repository so it is never empty, and gives you something to immediately clone or push to. A README file is the front page of your project — it explains what the project does, how to set it up, and any other details a visitor needs. Writing a good README is one of the most important habits in software development.

Create a new folder on your local machine to hold your project files. Open VS Code and use File → Open Folder to load that folder into the editor. Then open the integrated terminal via the three-dot menu → Terminal → New Terminal. You will see the terminal open at the bottom of VS Code, already pointed to your project folder path — this is where you will type all your Git commands.

With the terminal open, you are ready to connect your local folder to GitHub and push your files. The six commands below walk you through the entire process — from initializing Git in your folder to uploading everything to GitHub. Click each command to read a detailed explanation of what it does and why it matters.

// click on any command to learn more

01 git init Initializes a new Git repository ▼
This command creates a hidden .git folder inside your project folder. That folder is what makes it a Git repository — it stores the entire history of your project. You only run this once at the very beginning of a new project. Without it, Git has no awareness that your folder exists and cannot track any changes.
02 git add . Stages all files for commit ▼
The dot ( . ) means "add everything in this folder." This command moves your files into the staging area — a holding space where Git prepares them for the next save. Think of it like selecting all your files before copying them. Without this step, Git will not include your changes in the commit, even if you made them.
03 git commit -m "first commit" Saves a snapshot of your files ▼
This saves your staged files as a permanent snapshot in your Git history. The -m flag lets you attach a short message describing what you changed. Every commit is like a save point in a game — you can always travel back to it. Write clear, specific messages like "add radar sweep function" rather than just "update" so you can understand your own history later.
04 git branch -M main Renames the branch to main ▼
By default, older versions of Git create a branch called "master." GitHub and the wider industry now use "main" as the standard default branch name. This command renames your branch to "main" so it matches GitHub's expectation and everything syncs without any naming conflicts.
05 git remote add origin <URL> Links your local repo to GitHub ▼
This connects your local project folder to your online GitHub repository. "Origin" is just a standard nickname for the remote URL — you could call it anything, but "origin" is the universally accepted convention. Replace <URL> with the actual HTTPS or SSH link from your GitHub repository page. After this, your local Git knows exactly where to send your files.
06 git push -u origin main Uploads your code to GitHub ▼
This uploads all your committed files to GitHub for the first time. The -u flag sets "origin main" as the default tracking branch — so from this point forward, you can just type git push without specifying the destination every time. After this command runs successfully, your code is live on GitHub and visible to anyone with the link.

Once your code is on GitHub, you can publish it as a live website for free using GitHub Pages. Open your repository, click on Settings in the top navigation, then scroll down and select Pages from the left sidebar. Under "Build and deployment," set the source to your main branch and save. GitHub will automatically build and host your site within a few minutes.

Once GitHub Pages is enabled, a URL in the format username.github.io/repository-name will appear at the top of the Pages settings. Click "Visit Site" to open your live website. From this point on, every time you push updated code to the main branch, GitHub automatically rebuilds and redeploys the site — usually within 1–2 minutes. No hosting costs, no servers to manage.

Week 1 — Day 2 · Inkscape & Fusion 360

On the second day, we were introduced to two powerful design tools: Inkscape for vector graphics and Autodesk Fusion 360 for 3D CAD modelling. Both are industry-relevant tools that directly support the kind of product development and prototyping work done at Tinkerers' Lab.

Inkscape — Vector Graphics Editor

Inkscape is a free and open-source vector graphics editor used for creating scalable SVG files. It provides tools for designing logos, labels, enclosures, diagrams, and illustrations. The key advantage of Inkscape over raster editors like Photoshop is that its output never loses quality at any size — a logo designed in Inkscape looks equally sharp on a business card or a billboard.

Why Inkscape in an Engineering Internship?

In a product development environment like Tinkerers' Lab, design is not just about aesthetics — it is about precision and manufacturability. Inkscape exports SVG and DXF files that are directly compatible with laser cutters and CNC machines. This means a design you create in Inkscape can be sent straight to the laser cutter and physically cut from acrylic, wood, or cardboard. It bridges the gap between digital design and physical fabrication.

Types of Images

1) Raster Images — Composed of a fixed grid of pixels. Each pixel holds color information. When you zoom in or scale up a raster image, those pixels become visible and the image appears blurry or blocky. Common formats include JPEG, PNG, and GIF. Best suited for photographs and complex visual scenes.

2) Vector Images — Defined by mathematical equations that describe shapes, lines, and curves. Because they are based on geometry rather than pixels, they can be scaled to any size without any quality loss. Common formats include SVG, AI, and EPS. Best suited for logos, icons, technical diagrams, and anything that needs to be reproduced at multiple sizes.

Autodesk Fusion 360 — Parametric CAD Software

Autodesk Fusion 360 is a professional-grade computer-aided design (CAD) tool used for creating precise 3D models, assemblies, and technical drawings. It uses a parametric modelling approach — meaning every dimension and feature is defined by parameters that can be edited at any point without rebuilding the model from scratch. This makes it extremely efficient for iterative design, which is exactly how engineering prototypes are developed.

In Tinkerers' Lab, Fusion 360 is the primary tool used before sending any part to the 3D printer or laser cutter. Every physical component starts as a digital model — CAD ensures the dimensions are accurate and the design is manufacturable before any material is used.

Week 1 — Day 3 · Fusion 360 Hands-On

Day 3 was dedicated entirely to hands-on practice with Autodesk Fusion 360. Unlike the previous day where we were introduced to the tool conceptually, today we actually sat down and used it. Going in with little prior experience, I was surprised by how intuitive the workflow felt once I started sketching and applying operations. By the end of the session, I had completed my first proper 3D model.

Designing a Mug in Fusion 360

The task for today was to design a mug from scratch — a classic beginner exercise that covers the most important tools in Fusion 360. The process started with a 2D sketch on the canvas: drawing the profile of the mug (a cross-section shape) using lines and arcs. Once the sketch was defined and dimensioned, the Revolve tool was used to spin that profile 360° around a central axis — instantly generating the hollow cylindrical body of the mug.

The trickiest part was adding the handle. It required a separate sketch on a vertical plane, drawing the handle loop shape, and then using the Extrude tool to give it thickness. Joining it cleanly to the mug body required careful positioning. Seeing a flat sketch transform into a realistic 3D object that looks exactly like a mug you could hold — that moment made the whole session click. It was a great introduction to parametric modelling.

Filament Types

The choice of filament material directly determines the strength, flexibility, temperature resistance, and finish of a printed part. We work with four primary filament types:

PLA (Polylactic Acid) — The most beginner-friendly filament. It prints at relatively low temperatures, produces minimal warping, and is biodegradable. Ideal for prototypes, models, and display parts that do not face mechanical stress or high heat.

ABS (Acrylonitrile Butadiene Styrene) — Stronger and more heat-resistant than PLA, but requires higher print temperatures and an enclosed printer to prevent warping. Used for functional parts that need to survive real-world conditions — enclosures, brackets, and mechanical components.

PETG (Polyethylene Terephthalate Glycol) — Sits between PLA and ABS in terms of properties. Combines good strength with slight flexibility and is more moisture-resistant than both. A reliable choice for parts that need durability without the printing difficulty of ABS.

TPU (Thermoplastic Polyurethane) — A flexible, rubber-like filament that bends and compresses without breaking. Used for grips, gaskets, protective covers, and any component that needs to absorb impact or flex during use.

Bambu Lab H2D

The H2D is Bambu Lab's flagship industrial-grade 3D printer and the most advanced machine in our lab. Its standout feature is the dual nozzle system, which allows two different materials to be printed simultaneously — enabling multi-color prints, soluble support structures, and multi-material assemblies that would be impossible on a single-nozzle printer. The H2D also features a fully enclosed, heated chamber that maintains a stable temperature throughout the print — critical for materials like carbon fiber-reinforced nylon or PC that require consistent heat to avoid warping. With a build volume of 350 × 320 × 325 mm, an optional laser module for engraving, and AI-powered quality monitoring via its nozzle camera, the H2D represents the cutting edge of desktop additive manufacturing.

Week 1 — Day 4 · Logo Design in Inkscape

On Day 4, we returned to Inkscape with a more focused objective — designing an actual logo from scratch. This was the first session where we moved beyond exploring tools and had a concrete creative output to produce. As we grew more comfortable navigating the interface, the session evolved into a proper design workflow: ideation, sketching shapes, combining elements, and refining the final result.

How I Designed the Logo

I began by opening Inkscape and setting up a new document with a 500 × 500 px canvas — a square format that works well for logos since they are often displayed in square containers (profile pictures, app icons, stickers). I used the Circle tool with the Ctrl key held down to constrain the shape to a perfect circle. A gradient fill was applied to give the circle visual depth — moving from a darker tone at the edge to a brighter center creates a sense of dimension even in a flat design.

For the typography, I selected the Text tool and chose a bold, geometric font that felt modern and clean. The text was centered within the circle using Inkscape's alignment tools — Align and Distribute — to ensure it was perfectly positioned both horizontally and vertically. The final step was exporting the design as an SVG file, which preserves all the vector data and keeps the logo crisp and scalable at any size. Unlike saving as PNG, an SVG export means the logo can be scaled to any resolution without any quality loss — ready for use on a website, a laser-cut sign, or a printed label.
